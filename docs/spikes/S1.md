# S1: Rust Flecs bindings and reachable features

Date: 2026-11-09 · Status: **pass**, with one documented gap (`Parent`)
Tests: `spikes/flecs_features/tests/s1_features.rs` (kept as regression tests)

## Question
Which Rust Flecs crate and C Flecs version, and which features are reachable?

## Answer
- **Crate:** `flecs_ecs = "=0.2.2"` (MIT). It needs Rust edition 2024, which is why the toolchain is pinned to 1.99.1 (`rust-toolchain.toml`). The older `flecs` 0.1.x crate was not evaluated further.
- **Bundled C version:** Flecs **4.1.2** (`flecs_ecs_sys` 0.2.1). Asserted by `bundled_c_version_is_4_1_2`.
- **Features:** a reduced feature set (`flecs_base` + meta + json) fails to compile, because the pregenerated bindings reference the alerts addon. We use the crate's default features. That includes the HTTP/REST addons, but they do nothing unless they are started explicitly.

| Feature | Result | Test |
|---|---|---|
| `Parent` (non-fragmenting `ChildOf`) | **Gap: not in C 4.1.2.** `flecs::core::Parent` does not resolve, while `flecs::core::ChildOf` does. | `parent_is_not_in_this_version` |
| `OrderedChildren` | Wrapped (`flecs::OrderedChildren`, `set_child_order`, `each_child`). | `ordered_children_wrapped` |
| `OrderedChildren` by name lookup + add-by-id (Morgan's fallback hypothesis) | **Works.** The looked-up entity has the same id as the wrapped one. | `ordered_children_by_name_lookup` |
| `DontFragment` | Wrapped (`#[flecs(traits(DontFragment))]`). Setting such a component does not move the entity to another table, and queries still match it. | `dont_fragment_keeps_table` |
| Modules | Wrapped (`Module` trait, `world.import`). Contents are scoped under the module entity, and a module loads once. | `modules_scope_their_contents` |
| Observers with custom events and payloads | Wrapped. | `observers_with_payload` |
| Custom phases | Wrapped. Order follows `DependsOn`, not definition order. | `custom_phases_order_systems` |
| Disabling a phase | Excludes dependent phases' systems transitively. | `disabling_a_phase_excludes_dependents_transitively` |
| JSON serialization + reflection (meta) | Wrapped (`#[flecs(meta)]`, `to_json`). | `json_serialization_with_reflection` |

## Things learned about the binding
- Entity paths use `::`, not `.`: `flecs::core::ChildOf`.
- A module's path includes the Rust module path of the defining file (for example `::pong::sim::pong::core`). Look things up relative to the module entity (`module.lookup("Name")`), not by absolute path.
- Tags (zero-sized components) cannot be query fields with `.each`. They go in `.with(Tag::id())`.
- `flecs_safety_locks` (on by default) adds runtime borrow checks. They were not measured. Measure them before any performance work.

## Consequences
- **`Parent` is unavailable at the pinned version.** Design doc 6 and 9.1 (and spike S7, option B) depend on it. Options: (a) wait for a `flecs_ecs` release that bundles a newer Flecs C; (b) fork the bindings and regenerate them against a newer Flecs C (Morgan said this is acceptable, 3.4); (c) use option C from section 6, a plain owner component. Nothing in Milestone 0 needs `Parent`. **Decision needed from Morgan before M2 (UI hierarchy).**
- The `OrderedChildren` fallback question (3.4, [Open]) is answered: both the wrapped API and the name-lookup route work at this version.
