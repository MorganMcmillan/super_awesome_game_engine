# S5: SDL3 from Rust

Date: 2026-11-09 · Status: **partial**. Windows and Linux pass; the GPU-API triangle was not attempted.
Code: `crates/sage_platform`

## Choice
- `sdl3 = "=0.22.1"` (MIT) with `sdl3-sys` 0.7.3, which vendors **SDL 3.4.20** (zlib), built from source and linked statically (`build-from-source-static`). There is no DLL to ship and no system SDL to install. The cost is a first build of about 6 minutes, and it needs CMake and a C compiler (plus X11/Wayland/audio development headers on Linux; see the CI workflow).

## Results
- **Windows 11:** window, event loop, keyboard state, rectangle drawing and debug text all work with the simple Render API. `pong smoke` renders 90 frames, reads the last frame back and checks that court, wall, paddle and ball pixels are all present (`a2_window_opens_and_draws_court`, ignored by default because it needs a display).
- **Linux (Ubuntu 22.04, WSL2):** the static SDL build, all tests, and `pong smoke` under `xvfb-run` pass, with the build dependencies listed in the CI workflow.
- **GPU API + SDL_shadercross:** not attempted. SDL_shadercross is not installed, and building the offline shader toolchain was out of reach for this pass. The `sdl3` crate's `gpu-triangle` example (precompiled SPIR-V) shows the API is reachable from Rust; that was not run.
- **Keyboard play:** the key-to-`TickInput` mapping is unit-tested, and the windowed loop records input per tick. A person has not yet played a game with the keyboard.

## Recommendation for Milestone 0
Use the **simple Render API** as the throwaway Milestone 0 renderer (`SdlRenderer` behind the `Renderer` trait), as 13.1 allows. Start M1 with the remaining half of this spike: a GPU-API triangle with a shader compiled offline through SDL_shadercross.
