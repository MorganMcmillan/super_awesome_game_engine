# S3: Determinism replay harness

Date: 2026-11-09 · Status: **pass**
Code: `crates/sage_core/src/replay.rs`, `hash.rs`, `input.rs`
Tests: `crates/sage_core` unit tests, `examples/pong/tests/acceptance.rs`, `examples/pong/tests/cli.rs`

## Design
- `Simulation` trait: `step(TickInput)`, `tick()`, `state_hash()`.
- Input is data. The text format `sage-input v1` has a seed, a length, and the held buttons per tick (empty ticks are omitted).
- `state_hash` is FNV-1a 64 over explicitly little-endian bytes, with section tags. The caller feeds entities in `StableId` order (a `BTreeMap` index), never in Flecs iteration order. Pong hashes the clock, the current input, the RNG state, the game state, whether the `play` module is enabled, every entity's components, and **both** the current and the previous contact sets (design doc 8.2, rewind).
- `replay_twice` builds two fresh simulations, replays the recording on both, and reports the first tick whose hash differs.

## Results
- Pong, scripted game, seed 2026: identical hashes at every tick (`a1_replay_twice_matches_every_tick`). The replay also reproduces the recorded run's final hash.
- **Across processes:** two separate `pong replay` processes write identical per-tick hash files: 1281 lines, the initial state plus 1280 ticks (`a1_replay_matches_across_processes`). This would catch per-process nondeterminism, such as Python hash seeds, that an in-process test cannot.
- **Across builds:** the debug and release builds produced identical hash files for the same recording (checked by hand on Windows; CI runs both test suites).
- **Canary:** with `nondeterminism_canary`, a system folds over a `std::collections::HashMap` with `RandomState`. The harness reports a divergence at tick 0 (`a1_canary_is_caught`). A toy canary in `sage_core` is caught too (`hashmap_canary_is_caught`).
- **Python set canary:** not run in-process, because one process has one hash seed. The fixed seed is asserted instead (`sys.flags.hash_randomization == 0`), along with a test that a string set iterates in the same order regardless of insertion order. The cross-process replay test covers the rest.

## Limits
- **Across platforms (observed, not guaranteed):** replaying the committed recording (`examples/pong/tests/data/seed7_left_bot.txt`) gives byte-identical per-tick hash files on Windows 11 (MSVC) and Linux (Ubuntu 22.04, gcc), and S8's golden collision hash matches on both. The final hash is pinned in `committed_recording_reaches_game_over`. This holds because Pong uses only `+ - * /`, `abs`, `signum`, `clamp` and parry's cuboid contact. Transcendental functions or FMA could break it, so the 3.3 caveat still applies to new code.
