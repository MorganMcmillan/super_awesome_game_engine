# S8: Collision queries on parry

Date: 2026-11-09 · Status: **pass**
Code: `crates/sage_collision`. Tests: `crates/sage_collision/tests/s8_brute_force.rs`

## Setup
`parry2d = "=0.31.1"` (Apache-2.0; glam-based math through `glamx`). AABB colliders keyed by `StableId`. Broadphase: sweep and prune on x, sorted by `(min_x, StableId)` with `total_cmp`. Narrow phase: `parry2d::query::contact` on two cuboids, which gives the normal and depth. A pair is a contact only on **strict** overlap (`dist < 0`), so touching edges do not count. Output is canonical: `a < b`, sorted by `(a, b)`.

## Results
- **Same pairs as brute force:** 200 random layouts of 1–60 boxes, with input order shuffled and coordinates on a 1/16 grid so that exact edge contacts happen often. Every layout matches an independent all-pairs interval test that does not use parry (more than 1000 pairs in total).
- **Identical across runs:** the hash of contacts, normals and depths matches across repeated runs.
- **Identical across builds:** the same hash equals a golden value under both `cargo test` and `cargo test --release` (`identical_across_builds`).

## Contact table
`ContactTable` keeps the current and previous tick's sets. Begin, stay and end come from a sorted merge, so their order depends only on pair IDs. The previous set is part of the world-state hash, as 8.2 requires for rewind. The exercise-8 scenario is encoded as a unit test (`bounce_begins_once_per_contact`). It records what the table *does*: begin fires once per contact. It does not decide the [Open] question in 8.2. Milestone 0's Pong bounces on begin only, as a placeholder until Morgan answers exercise 8.
