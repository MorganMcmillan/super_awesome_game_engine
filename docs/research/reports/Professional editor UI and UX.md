# Great editors make novices rehearse expertise

Across CAD, creative tools, spreadsheets and game engines, the tools that serve every skill level do not ship separate beginner and expert products. They ship **one command set and one document reached through layered paths**. Each beginner action is visibly the same operation an expert types or scripts: AutoCAD's command line next to the ribbon, Blender's F3 search and keymaps next to its 2.80 toolbar, Excel's cells running from a typed number to LAMBDA and Python. The evidence also shows that **users do not climb those layers on their own**. Experienced users plateau, ignore printed shortcut labels and keep using slow menus, so the interface has to teach the faster path. Three more lessons recur. Professional tools keep the **recipe** (Onshape's feature list, Photoshop's layers, a spreadsheet's formulas) apart from the **result** and from **session history**. They show **why a value is what it is**: SolidWorks' degree-of-freedom colors, Excel's trace arrows, Blender's property decorators and Unity's runtime tint. And they put help **inside the editor at the point of need**. In the largest controlled study of game-making help (N=1646), interactive help came out best and text help did no better than none on most measures. Morgan's engine already holds the expensive parts of this picture. A game is a database, so it can have a spreadsheet view. Determinism makes parametric-history-style replay possible. Blocks are a lossless view of Python, which is the strongest rehearsal design the HCI literature describes. The open questions are about making those properties *visible*: authored versus runtime state, which system wrote a value, what an edit will touch, and what the next faster path is. This report separates sourced findings from the researchers' extrapolations. It frames engine-specific points as options for Morgan and resolves no [Open] or [Leaning] item.

**How to read the labels.** **[Source]** marks a finding reported by a cited primary or secondary source. **[Extrapolation]** marks a conclusion the researchers drew for this engine. **(unverified)** marks a claim the notes say was taken from a search summary or from memory, or was not re-checked against the primary text. No source studied an editor over a deterministic, replay-hashed ECS, so every mapping onto the engine is an extrapolation. The design doc already settles a lot. The editor follows the system theme, looks like Scratch 3.0, uses Godot-like tabs, has a Mario-Maker scene editor with a Flecs-Explorer-style component sidebar, and is built from the engine's own UI entities (10.6, [Decided]). Undo is a log of scene differences and play-in-editor works by snapshot (10.7 item 4, built in M3). The "Why?" button is principle 6. The report does not restate those decisions. It adds to them.

## One command set, many doors: the expert path must be taught, not just offered

The strongest pattern across the professional tools is a **flat namespace of commands reachable at several speeds**. **[Source]** AutoCAD's command line survived the 2009 ribbon because it is forgiving. Since AutoCAD 2014 it has autocorrected mistyped commands ("TABEL" becomes TABLE), searched mid-string, and mapped synonyms to commands (SYMBOL gives INSERT, ROUND gives FILLET), all on by default ([AutoCAD 2014 Preview Guide](https://jtbworld.com/download/autocad2014previewguide.pdf), from a search summary, unverified). The same commands are what AutoLISP calls. Autodesk added AutoLISP to AutoCAD LT in 2024 so that organizations could share their automation across both products ([Autodesk blog](https://www.autodesk.com/blogs/autocad/autocad-lt-2024-autolisp/)). Blender 2.80 (July 2019) added visible paths: left-click select, a persistent toolbar, task workspaces and an "Adjust Last Operation" panel. It also kept and extended the keyboard paths: three keymaps, including an "Industry Compatible" one, pie menus, Quick Favorites, and F3 search, which "searches all Operators within Blender, even if they are not exposed in a menu" ([Blender 2.80 UI notes](https://developer.blender.org/docs/release_notes/2.80/ui/); [Blender manual: Menu Search](https://docs.blender.org/manual/en/3.3/interface/controls/templates/operator_search.html)). The 2.8 design document says the new visual options are **an addition to shortcuts, not a replacement**, and the developers openly left the tension with expert speed unresolved ([Blender 2.8 Design Document](https://code.blender.org/2017/10/blender-2-8-design-document/); [Reynish 2018](https://code.blender.org/2018/04/tools-toolbar-and-tool-widgets/)).

Offering a faster path is not enough, because **users satisfice**. **[Source]** Bhavnani and John found that "despite experience, many users with basic command knowledge do not progress to an efficient use of complex computer applications", and they argued that strategy knowledge (use arrays, not repeated drawing) must be taught explicitly ([CMU HCI in CAD](https://www.andrew.cmu.edu/user/ujf/HCI_CAD.html); [Bhavnani & John record](https://acnpsearch.tweb-dev.unibo.it/singlejournalindex/79480775)). Lane et al. (IJHCI 2005) report that frequent users kept using menus for commands they used often, even though shortcuts are faster ([dblp](https://dblp.uni-trier.de/rec/journals/ijhci/LaneNPS05.html); the exact numbers were not retrieved). Scarr et al. explain why: switching modality causes a **performance dip** that users rationally avoid ([Scarr et al. CHI 2011](https://doi.org/10.1145/1978942.1979348)). The best experimental evidence on breaking the plateau is Grossman et al. (CHI 2007). **Hotkey labels printed beside menu items are commonly ignored.** In their main experiment, hotkey use rose from **28.9% in the control condition to 66.6% when the hotkey was spoken aloud on menu selection, and to 72.8% when menu items showed the hotkey but would not execute**. Extra visual decoration did not help ([Grossman et al. 2007](https://www.dgp.toronto.edu/~ravin/papers/chi2007_learninghotkeys.pdf)). Marking menus avoid the dip altogether, because the novice's visible selection is the same stroke the expert makes blind. In a field study a mark was about **3.5 times faster** than the menu, but the study had only two users ([Kurtenbach & Buxton CHI 1994](https://research.autodesk.com/publications/user-learning-and-performance-with-marking-menus/); [Berkeley summary](https://people.eecs.berkeley.edu/~fox/summaries/ui/marking_menus.html)).

How a tool hides features matters as much as what it hides. **[Source]** In a controlled study, static menus were significantly faster than adaptive (frequency-reordered) ones, and most participants preferred adaptable menus that they set themselves ([Findlater & McGrenere CHI 2004](https://www.cs.ubc.ca/labs/edapt/papers/findlater2004.pdf)). Reduced interfaces trade speed for awareness, because users know fewer of the features that exist (Findlater & McGrenere 2007, not re-fetched). Godot's feature profiles show the adaptable approach in a game engine. Since 3.2, teachers, studios and 2D developers can hide the 3D editor, docks, node types and individual properties ([Godot blog 2019](https://godotengine.org/article/godot-32-will-allow-disabling-editor-features)). The ribbon stories show the cost of reorganizing a GUI. Microsoft used opt-in telemetry and found that fewer than 2% of Office 2003 users customized their UI, so it designed for the default ([Jensen Harris, Part 8](https://learn.microsoft.com/en-us/archive/blogs/jensenh/grading-on-the-curve-why-the-ui-part-8)). AutoCAD's 2009 ribbon drew loud expert anger, which was eased by a kept "Classic" workspace that many users went back to before eventually returning to the ribbon ([cad nauseam](https://www.cadnauseam.com/2008/06/16/autocad-2009-why-do-you-hate-the-ribbon/); [Graitec](https://graitec.com/us/tech-resources/how-to-restore-autocad-classic-workspace/); the reaction evidence is self-selected and anecdotal). Search helps only when the user's word matches the tool's. Furnas et al. found that two people choose the same name for an object **less than 20% of the time**, so a command needs many aliases ([Furnas et al. 1987](https://doi.org/10.1145/32206.32212), not re-fetched). No peer-reviewed evaluation of VS Code, Sublime or Blender palettes turned up.

**[Extrapolation]** For this engine, the researchers read the evidence as follows. The block editor's lossless view of Python (4.1, [Decided]) is already a rehearsal design, as long as the Python is *visible* while a beginner drags blocks. The same idea can extend to the rest of the editor. Every editor action could be a named command with typed arguments, reachable from the GUI, from a forgiving palette (synonyms, autocorrect, results that show the shortcut, the menu path and the equivalent Python call), and from Python itself, so that a logged session becomes a script. Grossman's result suggests a nudge that is *not* visual, such as a disabled-menu "training" option or an audio cue, for users who opt in. A beginner layer should be one the user chooses (Godot profiles), never one the editor guesses. It should always come with a way to see what is hidden, for example a palette that searches everything. That fits principle 3, "nothing is hidden". This overlaps with the block-coding report's finding that learners use the palette to discover the API and drift back to blocks when new constructs appear. A command palette is the same discovery surface for the editor itself. Whether editor commands are a public Python API is a new surface. It would need a decision from Morgan, because it touches principle 4 ("built from its own public parts").

## Keep the recipe, the running world and the session apart

Every mature tool in the notes keeps separate what users want to change later, what is computed, and what is merely session history. **[Source]** Onshape stores three layers: UI state (selection, camera), the *definition* (the feature list), and *regeneration results*, which "are cached, but they can always be rebuilt from the definition". Each definition state is an immutable microversion holding only its changes, which address features by internal ID so renames do not break them. **Undo is per user and is a new inverse change appended to the history, never a rewind**, so it survives collaboration ([Baran 2015](https://www.onshape.com/en/blog/under-the-hood-how-collaboration-works)). Photoshop splits things the same way. The History panel (50 states by default) and snapshots last only for the session, while layers and generative layers are saved with the file and stay editable ([Adobe: History panel](https://helpx.adobe.com/photoshop/desktop/get-started/set-up-toolbars-panels/history-panel-overview.html); [Adobe: snapshots](https://helpx.adobe.com/photoshop/desktop/get-started/set-up-toolbars-panels/create-work-snapshots.html)). Figma's undo rule is that undoing a lot, copying, and redoing back to the present must leave the document unchanged, and redo must not overwrite other people's later edits ([Wallace 2019](https://madebyevan.com/figma/how-figmas-multiplayer-technology-works/)).

Game engines suffer most where this boundary is invisible. **[Source]** Unity discards edits made in Play Mode when play ends ([Unity Manual](https://docs.unity3d.com/Manual/ConfigurableEnterPlayMode.html)), and a 2025 bug report shows UI Builder losing unsaved work on entering Play Mode ([Unity Issue Tracker](https://issuetracker.unity3d.com/issues/ui-builder-unloads-uxml-file-and-discards-any-unsaved-changes-when-entering-play-mode-with-domain-and-scene-reload-enabled)). Unity's later Entities editor answered with a **data-mode switch** (Authoring, Runtime, Mixed). Runtime data that will be destroyed on exit is tinted orange in the dark theme and red in the light theme ([Unity Entities manual](https://docs.unity3d.com/Packages/com.unity.entities@1.0/manual/editor-authoring-runtime.html)). Getting this right took several package releases. Tomorrow Corporation's time-travel editor is **snapshot-based**: coarse snapshots every two minutes, plus fine snapshots made on demand and spaced exponentially further apart going back. Moving through time is not itself recorded, and forking from the past was left unbuilt. Blomquist says it works because the games' state is small ([Tomorrow Corporation 2023](https://tomorrowcorporation.com/?p=3022)). Niklas Gray lays out the trade-off for undo scope. Per-document undo breaks multi-file operations and renames, while a single project-wide stack surprises users by undoing changes in documents they have closed. He also argues for "a clear stance rather than many configuration options" ([Our Machinery archive](https://ruby0x1.github.io/machinery_blog_archive/post/the-document-model-and-the-machinery)).

Parametric CAD's history is the closest professional analogue to a deterministic simulation. **[Source]** Fusion highlights dependencies while you drag a feature through the timeline. Users report drags that fail silently and component moves that are lost when the history marker moves ([Autodesk forum](https://forums.autodesk.com/t5/fusion-support-forum/timeline-feature-requests/m-p/14293656), anecdotal). The documented failure is the **topological naming problem**: a later feature that refers to a face generated by an earlier one breaks when that face's identity changes. FreeCAD recommends referring to datum planes rather than generated faces ([FreeCAD wiki](https://wiki.freecadweb.org/Topological_naming_problem)). Onshape records lineage, so a reference can be re-resolved ([Onshape API docs](https://onshape-public.github.io/docs/api-intro/architecture/)). FreeCAD 1.0's fix is described as "not intended to fix every failure" by its wiki and as "(officially) history" by Ondsel, so the sources disagree on whether the problem is solved ([Ondsel](https://www.ondsel.com/blog/toponaming-problem-is-history/)).

**[Extrapolation]** The researchers see parametric history and the engine's replay as **the same idea at two layers**. A stored recipe (the authored scene, the Python and the input log) regenerates a cached result (every tick's world). Fusion's history marker becomes a tick scrubber. "Edit an early feature, regenerate, see what turns red" becomes "edit a rule, replay the recording, show `first_divergence`". Recorded *input* is naturally safe from the naming problem because it refers to no entities. A saved reference to an entity *spawned* during play is exactly a reference to a generated face. The CAD mitigations translate as options. Refer to authored entities by StableId. Give spawned entities lineage-derived IDs (spawner plus ordinal). Mark a reference broken, visibly, rather than silently rebinding it. Lineage-derived StableIds would change how IDs are assigned, which is determinism-critical, so they are a question for Morgan, not a recommendation. For the edit/play boundary, Unity's tint is the cheapest missing piece next to the Flecs-Explorer sidebar already decided in 10.6. The snapshot that play-in-editor already restores also makes an option Unity lacked: "keep this change" per value when play stops. Undo scope is live in the code today. `docs/milestone-4.md` notes that Python source edits are on no undo stack, and that one combined stack versus separate stacks is Morgan's call. Gray's two failure modes, together with Onshape's inverse-change undo, are the evidence for that decision. Finally, the creative tools keep **"undo edit" and "rewind tick"** as distinct controls over distinct histories (the authored document versus the running game). The block-coding report reached the matching conclusion from the other side: every Scratch-style liveness feature that changes the world must enter the simulation as recorded input at a tick boundary, or run in a throwaway fork. Principle 5 ("always live, always undoable") has these two meanings, and the UI probably has to show both.

## Show where every value came from, and what an edit will touch

Declarative and inherited systems feel like magic until they break. The tools that cope show **provenance and status on every element**. **[Source]** SolidWorks colors sketch geometry blue when it is under-defined (free to move), black when fully defined, and red when over-defined or unsolvable, and it offers SketchXpert to resolve conflicts ([SOLIDWORKS Help](https://help.solidworks.com/2019/english/SolidWorks/acadhelp/c_sketch_states_acadhelp.htm)). Third-party sources list other colors, and the scheme seems to have changed between versions. Blender 2.80 added property **decorators** showing whether a property is animated, keyframed, driven, linked or overridden ([Blender 2.80 UI notes](https://developer.blender.org/docs/release_notes/2.80/ui/)). Excel layers Trace Precedents and Trace Dependents arrows, Evaluate Formula (step through one sub-expression at a time), and green-triangle background error checking ([Journal of Accountancy 2024](https://www.journalofaccountancy.com/issues/2024/jun/how-to-find-errors-in-excel-formulas.html); secondary, no Microsoft page retrieved). Unity's 2018.3 prefab redesign responded to an Apply button that "could push changes to the asset unintentionally, with no good way to see what would be affected". The fix was a separate Prefab Mode, visible overrides, and apply per property, per component or per instance ([Unity blog 2018](https://unity.com/en/blog/technology/introducing-new-prefab-workflows)). The redesign drew forum complaints of its own ([Unity Discussions](https://discussions.unity.com/t/new-prefab-workflows-got-worse-unity-2018-3/725295), anecdotal). Figma keeps overrides per instance across swaps. Its 2026 rebuild replaced whole-instance re-resolution, which froze the editor on deep nesting, with dependency-tracked "derived subtrees", and variable-mode changes got **40–50% faster** in internal benchmarks ([Figma blog 2026](https://www.figma.com/blog/how-we-rebuilt-the-foundations-of-component-instances/)). Users still report nested overrides resetting unpredictably ([Figma forum](https://forum.figma.com/report-a-problem-6/overrides-on-instances-inside-instances-get-reset-inconsistantly-58140)).

The spreadsheet literature shows why this matters. **[Source]** Panko's pooled lab studies found a **3.9% cell error rate**, and he argues that 1–5% is what human-error research predicts ([Panko 2016](https://arxiv.org/pdf/1602.02601)). The Reinhart–Rogoff spreadsheet averaged rows 30–44 instead of 30–49, which left out five countries. That was one of several problems in the analysis ([New Statesman](https://www.newstatesman.com/business/economics/2013/04/statistic-cited-defend-austerity-partially-based-excel-error)). Public Health England silently dropped **15,841 COVID cases** when a legacy XLS template hit its row limit ([digit.fyi](https://digit.fyi/excel-error-blamed-for-16000-unreported-coronavirus-cases/)). Hermans adapted code smells to formulas and found them common and linked to real errors ([Hermans 2012](https://research.tudelft.nl/files/177578593/Hermans2012-formulasmells.pdf)). Reactive notebooks removed hidden state by requiring that **each global be defined by exactly one cell**, and they warn that in-place mutation is not tracked ([marimo docs](https://docs.marimo.io/guides/reactivity/)). Green and Petre's Cognitive Dimensions name the general failure, "hidden dependencies" ([Green & Petre 1996](https://doi.org/10.1006/jvlc.1996.0009), DOI from the notes, not re-fetched).

**[Extrapolation]** An ECS has the static dependency graph that marimo has to compute, because every system declares its query terms and phase. The researchers see one family of features built on that graph. The first is a per-field decorator in the inspector, showing whether a value is authored, inherited from a prefab, overridden, written each tick by a named system, or runtime-only. That merges Blender's decorators, SolidWorks' status colors and Unity's tint. The second is Excel-style tracing: select a component column and see every system that reads or writes it, and the reverse. The third is a "Why?" stepper that walks a system's query terms against one entity, like Evaluate Formula. The fourth is lints in the style of the green triangle, for example a component written by two systems in one phase (marimo's single-definer rule) or an entity with Velocity but no Position. The design doc already has pieces of this: the "affects 47 instances" count and override marks in 5.2 ([Leaning]), the "where" panel in 5.4 ([Leaning]), the hover pulse and "why is this system off?" provenance in 5.5. The research suggests treating them as **one provenance system** instead of separate widgets. Several adjacent items stay open and are not resolved here: state styles (9.2, [Open]), removing an inherited component from one instance (5.2, [Open]), and prefab override diffs in scenes, which Morgan deferred (10.4). The failure literature adds two cross-cutting options. Selections and bulk edits can be defined by queries or tags rather than hand-picked lists, because queries match by component and cannot "miss rows" the way the Reinhart–Rogoff range did. And every limit in a view, file or save can fail loudly rather than truncate. Because several of the source precedents signal status by color alone (SolidWorks' blue/black/red, Unity's orange/red tint), it is worth noting a constraint from the accessibility notes: color vision deficiency affects roughly 1 in 12 men ([Colour Blind Awareness](https://www.colourblindawareness.org/colour-blindness/), not re-fetched), and WCAG 1.4.1 forbids color as the only signal ([WCAG 2.2](https://www.w3.org/TR/WCAG22/)). The design doc already follows this rule for block shapes (4.2) and the phase pulse (5.5). The block-coding report's biggest worry, that ECS removes Scratch's "the sprite's scripts tell the whole story" locality, is the same problem seen from the beginner's side. A per-entity list of matching systems, with the systems that wrote each field marked, is that report's "story view" and Excel's Trace Precedents at once.

## Gentle slopes need constants that can grow into code

The spreadsheet is the most successful end-user programming environment because each step up costs little attention. **[Source]** Myers, Hudson and Pausch called a low threshold together with a high ceiling an important unsolved problem ([Myers et al. 2000](https://researchr.org/publication/MyersHP00)). MacLean et al. named the "customization gulf" and argued for a gentle slope, where each step needs only a small amount of new learning ([MacLean et al. 1990](https://researchr.org/publication/MacLeanCLM90), full text not read). Nardi and Miller found that a spreadsheet splits into a values layer and a formulas layer. The split lets people of different skill work on one shared artifact, and the "twinkling lights" of live recalculation keep them motivated ([Nardi & Miller 1991](https://www.lri.fr/~mbl/Stanford/CS477/papers/Nardi-Twinkling-IJMMS.pdf)). Blackwell models each step as an attention investment with an uncertain payoff ([Blackwell 2002](https://www.cl.cam.ac.uk/~afb21/publications/HCC02a.pdf)). Excel's layers all live in the same cell and formula bar: values, formulas, names, spilled dynamic arrays (FILTER, SORT, UNIQUE, previewed in 2018), LET and LAMBDA ("With LAMBDA, Excel has become Turing-complete") and Python ([Excel blog 2018](https://techcommunity.microsoft.com/blog/excelblog/preview-of-dynamic-arrays-in-excel/252944); [MSR podcast 2021](https://www.microsoft.com/en-us/research/?p=743248)). Python in Excel reached general availability on Windows desktop in September 2024 ([MC833882](https://app.cloudscout.one/evergreen-item/mc833882/)). Houdini does the same in parameters. A constant can become an HScript or Python expression, or a channel reference to another parameter ([SideFX docs](https://www.sidefx.com/docs/houdini/network/expressions.html)). A whole network can be wrapped into a digital asset, a new node type with a curated, promoted interface, versioning, and an expandable file format for source control ([SideFX: Digital assets](https://www.sidefx.com/docs/houdini/assets/index.html)). Through Houdini Engine those promoted parameters become the inspector inside Unity and Unreal ([Houdini Engine for Unity](https://download.sidefx.com/docs/unity18.0/_parameters.html)). Database-as-app tools add typed fields, linked records with lookup and rollup, and several saved views (grid, kanban, gallery, calendar) of one table ([O'Reilly, *Learning Airtable*](https://www.oreilly.com/library/view/learning-airtable/9781098133368/ch06.html)).

The ceiling has its own warnings. **[Source]** On SideFX's own forum, users say procedural modeling is "much harder to understand in actual practice" than direct modeling, and many build a procedural base and then "bake" it ([SideFX forum](https://www.sidefx.com/forum/post/144434/)). A beginner guide warns that shelf tools silently build multi-level networks that beginners cannot read ([Medium](https://medium.com/@sarah.hyperdense/houdini-for-the-first-time-interface-nodes-and-the-procedural-mindset-6721c1cc5613), anecdotal). Fusion's guidance is to mix parametric and direct edits, "the best tool for the situation" ([Autodesk blog](https://www.autodesk.com/products/fusion-360/blog/timeline-edits-in-fusion/)). Reactive notebooks show the cost of hidden state. One large GitHub study reported that only a small fraction of Jupyter notebooks reproduced their results ([Pimentel et al. 2019](https://doi.org/10.1109/MSR.2019.00077); the notes give about 24% running without errors and about 4% reproducing, both from memory and unverified).

**[Extrapolation]** Principle 1 ("a game is a small database") makes the spreadsheet mapping almost literal. A query result could be a live table: entities as rows (StableId as the row number), fields as columns, the matched count updating each tick, and selection synced with the scene view. Airtable-style saved views could give a kit or a teacher a curated "Enemies: name, speed, health" table with the schema hidden. A visual filter that compiles to query terms, with the generated Python shown beside it, would extend the blocks-teach-Python rehearsal to queries. The block-coding report's caveat applies: no source shows that query builders teach the text language, so this is a hypothesis to test with users. Houdini's digital asset suggests a capability boundary. An author would mark which fields of a prefab or kit system form its public interface, with ranges and units, and instances and the block palette would show only those. That fits the block-coding report's finding that a curated, game-level vocabulary matters more than block mechanics (4.7, [Leaning]). Inspector fields that accept an expression instead of a constant are the most powerful slope in the notes and the most expensive. Expressions would have to run deterministically inside the simulation, be hashed, and be stored in `sage-scene`, which is a file format change. So they are a question for Morgan, not a proposal. The shelf-tool warning gives a firm rule for any wizard: whatever a helper generates must be readable Python and visible entities. Principle 3 already says "nothing is hidden".

## The first hour is help in context, with game words and a box to work in

**[Source]** The largest controlled study of help in game-making software (Kao, FDG 2020, N=1646, six conditions) found that **interactive help had the largest positive effect** on time spent, learnability, motivation, cognitive load, editor activity and level quality, with video a close second. **No help was worst on every measure, and text help was statistically no better than none** except on cognitive load. Of 85 game-making tools reviewed, few had interactive help ([Kao 2020](https://arxiv.org/abs/2006.03519)). Autodesk's ToolClips (tooltips with short videos) let users complete **seven times as many unfamiliar tasks** as a professional online help system, and they were faster a week later ([Grossman & Fitzmaurice CHI 2010](https://research.autodesk.com/app/uploads/2023/03/toolclips-an-investigation-of.pdf_recbnW20cbxDanglq.pdf); sample size not checked). Grossman, Fitzmaurice and Attar separate *initial* learnability from *extended* learnability, which covers getting better over time and switching to efficient behaviors ([Grossman et al. CHI 2009](https://research.autodesk.com/app/uploads/2023/03/a-survey-of-software.pdf_recqWPTEYd6nsP0r8.pdf)). Beginner tools also succeed through **constraint plus completeness**. PICO-8 opens to a shell with code, sprite, map and sound editors, and its limits are "carefully chosen to be fun to work with" ([Raspberry Pi Magazine](https://magazine.raspberrypi.com/articles/pico-8-review)). Bitsy's 8×8 tiles and two-color palettes are deliberate ([Wired](https://wirednews.pages.dev/story/you-make-fun-games-no-experience)). Dreams teaches through in-game guides, a starter game built with the same tools, and first-class remixing ([PlayStation](https://www.playstation.com/en-us/editorial/dreams-beginners-guide)).

Words and surfaces matter as much as help. **[Source]** In a 2023 forum thread, Unreal beginners complained about a Content Browser drawer that hides on any click, an Outliner cluttered with rarely used actors, and the word "Actor" ([Unreal forums](https://forums.unrealengine.com/t/improving-the-first-user-experience-of-the-editor-to-attract-new-developers/1307824), anecdotal). Adobe's four rounds of research on Photoshop's Reference Image found that "generative compositing" and layers confused newcomers. A continuous slider was cut to two positions, and the lesson recorded was to "adapt the technology to user behavior" ([Adobe Design](https://adobe.design/ideas/behind-the-design-adobe-photoshop-reference-image)). Photoshop's contextual task bar puts the next likely action beside the selection, on by default and easy to hide ([Adobe](https://helpx.adobe.com/photoshop/using/contextual-task-bar.html)). Its Discover panel shows the opposite. Experts complain that it pops up over their work, and the threads show no official way to turn it off ([Adobe Community](https://community.adobe.com/t5/photoshop-ecosystem-discussions/how-do-i-disable-the-discover-panel/m-p/13804363)). For customization, Mackay found that lack of time was the main barrier and that customizations spread socially through shared files ([Mackay CHI 1991](https://www.lri.fr/~mackay/pdffiles/CHI91.Triggers.pdf)). Making customization visible and social changed behavior significantly ([Banovic et al. CHI 2012](https://research.autodesk.com/app/uploads/2023/03/triggering-triggers-and-burying.pdf_recQmDHm7lgNUZAhp.pdf)). Godot supports named, saved layouts per task ([Godot docs](https://docs.godotengine.org/de/4.x/tutorials/editor/customizing_editor.html)). Fusion and Shapr3D ship navigation presets that copy other CAD tools, an open admission that muscle memory is a switching cost ([Autodesk Fusion preferences](https://help.autodesk.com/cloudhelp/ENU/Fusion-GetStarted/files/GUID-878489CD-3A23-4303-8450-C2F4F8E410B1.htm)).

**[Extrapolation]** This lines up with the block-coding report. Fraser found that popups which close only when the student performs the action were what worked, and Resnick argued for templates that invite change rather than puzzles. Kao's controlled result now gives that advice its strongest quantitative support: onboarding should be tutorials that drive the real editor on a real project (Pong exists), built as editor-side observers that wait for the action. A contextual "next action" bar near the selection ("Add component", "Make prefab", "Play from here") follows Photoshop. The Discover complaint sets its conditions: on by default, never uninvited, dismissible forever. Labels should name outcomes ("make copies follow this one", "reset to prefab") rather than mechanisms ("IsA", "override"), and game words ("Player", "Coin", "moves like a platformer") should come before engine words. Saved layouts, keymaps and navigation presets ("Godot-like", "Unity-like", "Aseprite-like") are cheap because `InputMap` is already data. Storing them as project text files would serve Mackay's social spread, but any new text format needs Morgan's approval. The tear-off tabs in 10.6 bring a known risk of layout chaos, and a one-click "reset layout" is the vendor-tested remedy. Kao's text-help result and Grossman's extended-learnability distinction suggest measuring how users progress: opt-in, local usage counts of whether people find the palette, hotkeys and Python, the way the ribbon team used telemetry. That is a privacy and scope decision for Morgan.

## Conclusion

The research shifts the question from "beginner mode versus expert mode" to "how does each action advertise the next faster one?" The engine's architectural bets match what the best professional tools built expensively and late: text as truth, a database world, deterministic replay, and scene diffs. Unity needed several package releases to settle data modes, and Figma rebuilt its instance system in 2026. In this engine those properties exist below the UI, so the work left is mostly *display*: tinting, provenance, tracing, previews of blast radius, and showing the Python behind every gesture. The least obvious finding is that parametric CAD's long struggle with the topological naming problem, still only mitigated by heuristics in commercial kernels, is a preview of what happens when replays and saves refer to entities spawned during play. Recorded input is immune; entity references are not. That is cheap to decide now and costly to retrofit.

Two findings challenge assumptions a designer might hold. First, availability is not adoption. Experts plateau on slow paths, printed shortcuts are ignored, and text help measures no better than nothing, so a high ceiling the UI does not actively teach is a ceiling few users reach. Second, the dangerous moments in professional tools are boundaries: edit versus play, prefab versus instance, recipe versus result, my undo versus the world's rewind. The block-coding report found that Scratch's power comes from the loop around the blocks rather than the blocks themselves. This report finds the same about the editor: the quality of its boundaries, more than its panels, will decide whether the low floor and high ceiling hold together.
