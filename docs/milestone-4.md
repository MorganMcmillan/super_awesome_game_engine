# Milestones 3 and 4: the editor and the block round trip

Date: 2026-11-13. Scope: design doc 13.3, **M3** "editor core: inspector, undo/redo, play-in-editor, text editing of Python" and **M4** "block editor round trip (`libcst`), palette generated from reflection". The UI they stand on is `docs/milestone-3.md` (the UI parity phases, which that file calls M3 for historical reasons).

Asked for by Morgan's `/goal` ("implement the engine up to milestone 4 ... only the editor features that are in the docs"). The design doc gives these milestones no acceptance list, so the checks below are mine, as for M1 and M2. Please confirm or replace them.

Decisions Morgan made in this session: **use `libcst`** (not `ast` plus text splicing, which I had started) and **comments are sticky notes** joined to the block below them, docstrings included. Both are recorded in design doc 4.1 and `docs/dependencies.md`.

## What was built
- `crates/sage_editor` (no window, no device):
  - `history`: undo and redo as a log of scene differences (`SceneDiff`), with merging of edits to one field until the gesture ends (a drag is one step).
  - `document`: the authored `Scene`, selection and history; the inspector (`inspect`) and outliner (`outliner`) generated from the reflected schemas; add, rename, duplicate, delete (with children), add and remove component, set a field from text (typed, finite floats only).
  - `project`: Python sources, a live world and the document. Edit mode keeps the world equal to the scene; play in editor snapshots the world and `stop` restores it exactly; live reload builds a fresh world from changed sources and carries the scene over (a failing script keeps the old world and reports why).
  - `blocks.rs`: installs `sage.blocks` into the embedded interpreter and runs the Python tests.
- `python/sage/blocks.py` (needs `libcst`): Python source to blocks and back.
  - `parse` builds plain-dict blocks (statements: assign, change, declare, discard, if/elif/else, while, for, return, pass, break, continue; expressions: typed literals, names, attributes, calls with keywords, operators, comparisons, conditional expressions, subscripts, list, tuple, set, dict).
  - `Blocks` edits: `replace`, `set_literal`, `insert`, `delete`, `move`, `add_else`, `set_notes`, `set_docstring`, `add_function`, `delete_function`, `rename_function`, `set_position` (`@sage.position(x, y)`). Each rewrites the concrete syntax tree at the touched node and prints it again; a failed edit changes nothing.
  - A function using anything else (f-strings, lambdas, comprehensions, `try`, `with`, slices, `*args` calls, statements sharing a line, parameter defaults...) is **locked**: shown read-only, never touched. No raw-code block (design doc 4.1).
  - `palette(schemas, scope)` generates blocks from reflection: get, set and change per field (change only for numbers), add, remove and has per tag; a component in the stack's scope reads through its parameter (`pos.x`), any other needs an entity socket (`e.get(C).x`); each module is a category. `core_palette` has Control, Variables, Operators, Values and Calls.
  - Notes: the comment lines above a statement, function or top-level item are its `notes`; a function's docstring is its `doc`; a comment after a statement is `trail`. `set_notes` and `set_docstring` edit them.
- `sage.position` in `python/sage/__init__.py`: a no-op decorator that records where a stack sits.
- `sage_ecs_py::Ecs::load_with`: load a script with extra globals (the host object).
- `examples/editor` (`cargo run -p editor -- play [--project DIR]`, `-- render --out FILE.png [--tab SCENE|CODE|BLOCKS] [--select SID]`, `-- smoke`): the editor, written as UI entities in `scripts/editor.py` over the widget kit (design doc 10.6). Top bar (undo, redo, play/stop, step, reload, save, status), outliner, scene viewport (click selects, drag moves), inspector, code tab (APPLY reloads live), block tab (palette, stacks, sticky notes). A project is a directory of `.py` files and `scene.sage`; without `--project` a small sample game opens.

## Setup note
The block editor needs `libcst`, a Python package with a native part, per Python version: `python -m pip install --target python/vendor/py312 -r python/requirements.txt` (use `py314` for 3.14, and so on). On this machine the embedded interpreter turned out to be **3.14**, not the 3.12 `CLAUDE.md` names (PyO3 links the `python3` on `PATH`); both are installed in `python/vendor`. CI installs 3.12.

## Gaps and things I could not check
- **Blocks are placed by drag and drop or by clicking.** A palette entry can be dragged onto a statement (inserts before it), a stack's hat (appends) or a value (replaces it), a statement's head can be dragged onto another statement or a hat, and stacks are moved by their grip on the canvas, which writes `@sage.position`. Clicking a palette entry still works. Not built: typed-socket highlighting while dragging (a value dropped on any value slot is accepted; the Python text checks the result), and dropping onto the gap *between* nested blocks other than "before this one" or "end of this stack".
- **Shapes (design doc 4.2, still [Open]):** commands have a notch under them, values are round, tests are square with a dark outline, types are square with a thicker one. They are rounded boxes with outlines, not Scratch's notched silhouettes, so the type-versus-slot distinction is by outline and radius, not by a unique outline shape.
- **"Why?" and glow:** a runtime error (from play or step) is shown on the block whose source line the traceback names, with the message under it. Active blocks glow while running, and PAUSE and STEP hold and advance the game. Not built: a profiler and "why is this system off?".
- **`settings.sage`** (project settings, one `key value` per line, written only when a setting was set) is a new small text format; it needs Morgan's confirmation like the other formats. A long value (list, grid, call, comprehension) is drawn on its own line under the block's words, because a row cannot wrap an expression.
- Typed sockets (design doc 4.2, 4.4, 4.6) are editor-side: a slot that wants a test, a number or text refuses a value whose type is known to be different (`type_of`), and takes anything of unknown type (names, calls, attributes: `any`); lists carry element types (4.4). The hover delay and pulse count are settings on the TIMING tab. Not built: the stack canvas's auto-layout of overlapping cards. f-strings, `try`, `with`, slices, starred arguments and statements sharing a line still lock the function.
- **Keyboard shortcuts** are the kit's chords. Arrow keys (with Ctrl or Alt) and Delete became chord keys (`CHORD_UP` to `CHORD_DELETE`, `ui.parse_chord("Alt+Up")`), so the shortcuts are the ones proposed. Delete only deletes a block when focus is not in a text field. They are real buttons in a row at the bottom, so they can be seen, tabbed to and pressed. Enter on a selected block is told from a click by the navigation bits of that tick. Only blocks are keyboard-reachable for insertion by a *palette* (Ctrl+B and Ctrl+E); dragging remains mouse-only, and the timing and prefab tabs are reached by Tab and Enter only. Not verified with a real screen reader: the roles and names are in the accessibility tree (`access_outline`), and the Linux and macOS adapters are not approved.
- **Phases and prefabs** are edited in the script text (`X = world.phase("X", after=Y)`, `world.prefab`), found by shape at the top level. The graph is columns by depth with a drop-down per phase, not dragged edges with hover pulses; prefab instance counts count `IsA` pairs in the scene by target name and may read 0 until the scene format records them that way. Phases are not disabled themselves (design doc 5.5 says modules are what pause); the crosstab and the "why is this system off?" provenance read the live world's module switches, so a module the script does not bind to a variable cannot be toggled.
- Glow needs instrumented scripts (the editor turns that on); the hit record is per OS thread, so two editors on one thread would share it.
- A long block row is cut at the right edge of its stack card and scrolls with the canvas; very long comprehensions are hard to read.
- Comments that are not directly above a statement or function (inside an expression, at the end of a body, before `else:`) are kept in the text but not shown. Docstrings of classes and modules are shown as plain text or a file note, not editable as notes. Notes on `else:` and on parameters are not supported.
- Editors beyond the scene, code and block views are not built (design doc 10.6 says the others are "yet to be identified"): the prefab editor, phase editor, game-state editor, profiler. Dropping a component onto a prefab or an instance (5.2) is not built; components are added from a drop-down.
- Scenes store full component values (M2 decision 3), so there is no apply/revert for prefab overrides.
- The scene viewport draws every entity that has a `Position`-like component (float `x` and `y`) as a box sized by `hx` and `hy` (or half_x and half_y); there is no sprite or camera preview. Moving works on the first such component.
- Undo is a transaction log over whole-entity scene differences, and the live world reloads the scene after each edit. It is fine for hand-sized scenes, not for thousands of entities, and a reload resets any Python state kept in the world outside components.
- The inspector shows string fields (interned ids) as numbers, and has no widgets for arrays or nested structs (the binding has none).
- Tab tear-off into sub-windows (10.6) is deferred, as in the UI parity plan.
- The editor's own view state (which tab, the palette category, the selected block) is Python variables, not components, so it is neither saved nor replayed. The document is the state that matters.
- `libcst` is slower to start than `ast`; a parse per edit is imperceptible at file sizes here and untested on thousands of lines.

## Known issue: an intermittent abort in full test runs
`cargo test --workspace` aborted with SIGABRT (no message) three times in about fifteen full runs: once in `ui_playground`'s tests and once in `sage_ecs_py`'s binding tests, both right after tests start, and once earlier in a run that was killed. It did not reproduce in 25 repeat runs of the binding tests or 6 of the playground tests alone, and the last three full runs passed. All the tests that abort embed Python and Flecs on many threads at once. The cause is not found; `CLAUDE.md` already warns that script objects are cyclic garbage that Python may free on any thread, which is the first place to look. Re-run a failing workspace run before suspecting a change.

## Window startup on Wayland (fixed 2026-11-13)
On some GNOME Wayland machines `cargo run -p editor` aborted with `GLib-GIO-ERROR: Settings schema 'org.gnome.settings-daemon.plugins.xsettings' does not contain a key named 'antialiasing'`: SDL's libdecor GTK plugin reads a settings key the machine's schema lacks, and GLib aborts the process. `sage_platform::prepare_video` (called before every SDL init) now prefers X11 (XWayland) when `DISPLAY` is set and `SDL_VIDEODRIVER` is not, with Wayland as the fallback. `SDL_VIDEODRIVER=wayland` still forces Wayland; if that aborts, `SDL_VIDEO_WAYLAND_ALLOW_LIBDECOR=0` skips the plugin (the window may then have no title bar on GNOME). Checked by running the editor and the playground smoke commands with no environment variables on this machine.

## Responsiveness (2026-11-13)
The editor felt sluggish: every change rebuilt every view, including the hidden tabs (the timing and prefab tabs cost about 17 ms each and the block tab about 19 ms, so a rebuild took about 60 ms even in a release build, and dragging in the scene rebuilt them on every pointer move). Now only the status, outliner, inspector and the tab that is showing are rebuilt, and a hidden tab is rebuilt the moment it is opened; the last few libcst parses are cached (the position metadata was most of the cost); handler tables are pruned of dead widgets instead of cleared; and the dev profile optimizes the workspace's hot crates (`sage_ui`, `sage_platform` and others), since `cargo run` is a dev build. Measured with `cargo run -p editor --example bench` (dev build, milliseconds): idle tick 0.5, rebuild on the scene tab 0.8 (was 68), on the block tab 10 (was 72), on the timing tab 4; drawing 2.4; a live reload after a block edit 30. A hidden GPU window averaged 166 fps on the block tab. `editor play` prints its average fps and ticks per second on exit. Still slow: a live reload takes about 30 ms, so a burst of block edits can feel heavy; debouncing it is the next step if that shows.

## Editor polish pass (2026-11-14), asked for by Morgan
Goal: make the editor look as professional and user-friendly as possible. Agreed with Morgan in a grilling session first.
- **Font:** the editor draws with Liberation Sans (Arial-metric-compatible, SIL OFL; Arial itself cannot be redistributed), shaped and proportional. `docs/dependencies.md` has the license. Games keep the pixel face.
- **Capitalization:** no all-caps UI text. Rules in `docs/ui-style.md`. Names from the project are shown as written (they were upper-cased before).
- **Right-click menu** replaces the row of small buttons (note, delete, up, down, run to here) on every block. Add note, Remove note, Move up and down, Add else branch, Run to here, Delete block. The same actions keep their shortcuts (Alt+N, Alt+Up, Alt+Down, Alt+L, Del). Tests: `the_block_menu_deletes_reorders_and_notes`.
- **Notes are separate cards.** Comments parsed from Python still attach to the one block below them (that is the model, and the text on disk is unchanged). The editor draws each as its own card beside the stack, joined to its block by a line, and a note moves on its own by its top strip. Test: `a_note_is_a_card_apart_from_its_stack_and_moves_on_its_own`. **Gap:** where a note was dragged to is not saved (a session offset keyed by the note's text); saving it needs a format decision for Morgan.
- **Scratch-style dragging.** A stack moves when it is dragged by any part that is not a block; a block dragged from inside a stack takes every block below it (`Blocks.move_tail`), and can be dropped before a block, at the end of a body or stack, or on bare canvas, where it starts a new stack (`stack_N`). The dragged blocks follow the pointer, held where you picked them up; the drop target is worked out from the pointer, ignoring the blocks carried. Tests: `python/tests/test_blocks.py` (`test_dragging_a_block_takes_everything_below_it` and two more) and `editor.rs`. **Gaps:** no snap preview or insertion marker while dragging, and dropping between nested blocks still means "before this block" or "end of this body". The stack grip is gone.
- **Not started from the agreed list:** the Mario-Maker-style prefab and component bar over the scene, the library of standard components, and the home-screen layout (viewport, outliner and blocks together). Contrast checks and the spacing and size scale are also not done.
- **Delete a stack:** right-click a stack's hat for Add Note, Remove Note and Delete Stack. It asks first, naming how many blocks go. Test: `a_stack_is_deleted_from_its_hat_menu_after_asking`.
