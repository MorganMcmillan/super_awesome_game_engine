# Milestone 5: the platformer kit

Date: 2026-11-14. Scope: design doc 13.3, **M5** "first genre kit, extracted from the platformer dogfood game". How to use the kit, and what an artist needs to draw, is `docs/platformer-kit.md`.

Asked for by Morgan's `/goal` ("implement the milestone 5 genre kit, and a platformer example that uses it ... extremely basic low-poly assets, as later I will hire a human artist to finish the genre kit's art ... welcome to interview me"). The design doc gives M5 no acceptance list, so the checks below are mine, as for M1 to M4. Please confirm or replace them.

## Decisions Morgan made (the interview)
- **Movement feel:** classic Mario-like (momentum, a run button, stomping), not Celeste-like and not minimal. Everything is tuning data, so the defaults can change.
- **Mechanics in the kit:** patrol enemies with stomping; coins, hazards and checkpoints; moving and one-way platforms; and, in Morgan's words, "wall jump, roll, dive, mid-air spin". Not chosen, so **not built**: a goal flag and a level list.
- **Art:** plain colored rectangles. I read "low-poly" in the goal as "flat shapes with no detail"; the only polygons are the triangular hills in the scenery.
- **Levels:** ASCII text pictures. This is a new text format (`load_level`'s legend); Morgan chose it, so it counts as confirmed.

## What was built
- **`crates/sage_platformer`** (a simulation crate: no window, no audio device). The kit is split the way design doc 4.1 and 8.1 ask: native where it must be fast and exact, Python where it is the game.
  - Native (`src/`): `sweep` (pure move-and-collide of boxes against solid boxes: axis by axis in steps of at most 4 units so nothing tunnels, flush stops, floor, wall, ceiling, headroom, ledge probes, one-way platforms, pushing out of a moving solid); `vocab` (components under `sage.platformer`: `Velocity`, `Body`, `Solid`, `Look`, `Camera`, `Backdrop`); `kinematics` (the native `kinematics` flecs module: one system that moves every `Body`, collides it with every `Solid`, carries riders of moving solids and pushes bystanders, in StableId order); `frame` (the world as a `UiFrame`: sky gradient, parallax triangle hills, boxes or sprites sorted by `(layer, StableId)`, hearts and coin text, a pause or death overlay; everything snapped to whole units); `lib` (`Platformer`: loads the kit and a game's scripts into one world, steps the fixed tick, snapshots, saves, derives sound cues from `Tally` counters, answers questions for tests and bots).
  - Python (`scripts/`, read in this order): `vocabulary.py` (components, `Tuning` and `Rules` numbers, phases, the `play` and `core` flecs modules, the `world.platformer` namespace), `player.py` (eight modes: ground, air, wall, duck, roll, dive, spin, hurt), `actors.py` (walkers, movers, coins, spikes, checkpoints, the contact observer), `level.py` (`load_level`), `rules.py` (pause, death and respawn, falling out, the eye, the camera).
- **`crates/sage_collision::ecs`:** Pong's native collision vocabulary (`Position`, `Collider`, `ContactBegin`, `Input`, `Clock`, the contact table and the `collision` flecs module) moved out of `examples/pong` so the two games share it. No behavior changed; the golden hashes and all Pong tests pass as before.
- **`crates/sage_platform::game_window`:** `GameApp` (a `Simulation` that draws itself as a `UiFrame` and emits cues), `run_game_windowed` (the fixed-tick window loop with recorded button input, cues and the GPU renderer, GPU only like the UI window) and `render_frame` (the CPU reference, for screenshots and tests). `sage_core::host` is unchanged.
- **`examples/platformer`:** `scripts/game.py` is the game: two tuning numbers, a sky, a 124 by 14 tile level drawn as text (start, a gap, a walker, a one-way platform with coins, spikes, stairs, a checkpoint, a pit with a stepping stone, walkers, a sliding platform, a wall-jump chimney, a second checkpoint, a last stretch) and one rule of its own (ten coins earn a heart). The Rust side adds a window, keyboard and gamepad map, placeholder sounds (`platformer gen-assets`, committed in `assets/`) and `Bot`, which plays the level from its picture.
  - `cargo run -p platformer -- play` (arrows or WASD, Space or Z jump, Shift or X run, C or V spin, P or Enter pause, Esc quits), `headless`, `replay FILE [--hashes OUT]`, `smoke`, `render --out FILE [--ticks N]`, `gen-assets`.
- `python/sage/platformer.pyi`: generated editor stubs for the native vocabulary (`UPDATE_STUBS=1 cargo test -p platformer --test stubs`).

## Deviations from the design doc, and how to read them
- **Process:** design doc 13.3 and 11 say a module becomes a kit only after a second game reuses it, and that M5 is "extracted from the platformer dogfood game". I wrote the kit and its first game together, at Morgan's request, so nothing was extracted over time. Two reuses exist: Pong shares the `sage.collision` vocabulary and `collision` module, and the 12-line "moon" game in `diff.rs` is a second game on the kit. Whether that is enough to call it promoted is Morgan's call; the [Leaning] tag in 11 is unchanged.
- **Shared core vocabulary (exercise 15, [Open]):** `Health`, `Score`, `Respawn` and the rest are **kit-local** components in `platformer.*`, not a shared vocabulary. I did not decide what the shared one is. Moving `Health` into a shared module later means a scene migration (rename component) and nothing else.
- **Integer-position controller (design doc 8.1):** the doc suggests integer positions for the platformer (as in Celeste). Positions are `f32`, bodies stop flush against edges and a small epsilon decides touching, and everything is plain `+ - * /` arithmetic (no fused operations), so a run replays exactly on one machine. **Cross-platform float determinism (Linux versus Windows hashes) is not verified.** If it matters, integer positions with a remainder is the usual fix.
- **Kits are packages (design doc 7, 10.3):** a kit here is a crate that embeds its scripts, not a package with a manifest, a version, dependencies and license tracking. A manifest would be a new file format; I did not invent one.

## Gaps and things I could not check
- **Not built (not chosen):** a goal flag and a level list. The level has an end wall and nothing happens there. Adding a goal is a `Goal` tag, one contact rule and `load_level` for the next picture.
- **Feel is by numbers, not by hand.** I tuned against the tests and the bot (measured: a standing jump held to the top rises about 70 units, a running one about 80 units, 5 tiles, and travels about 117 units, 7 tiles), not by playing for an hour. Please play it (`cargo run -p platformer -- play`) and tell me what feels wrong; `kit.tune(...)` is the place to fix it. Sound is checked by the mixer and the device opening, not by ear; a gamepad is bound but untested.
- **No animation.** A sheet shows one cell per player mode and the sprite mirrors, but nothing animates (the design doc lists animation as later). Enemies, coins and tiles have one image each.
- **Moving platforms** do not push sideways when they are one-way (all the level's are); a solid mover pushes and sets `Body.squeezed`, but no rule crushes. Platform paths are back-and-forth only (`Mover`).
- **Low ceilings:** every tile is 16 high and the player is 14, so no tile gap forces a crouch; the crawl-under-a-low-ceiling code path (`roll` and `duck` refuse to stand without headroom) is covered by the sweep's headroom test but not by a level.
- **Linear scan:** `kinematics` tests each body against every solid (hundreds in the example). A grid broadphase (design doc 8.1: "for grid worlds the grid itself is the broadphase") is the next step for big levels. Tiles are one entity each, not merged.
- **Scenery is generated, not authored:** hills come from a fixed hash of their index; tiles have no autotiling (grass on the top row, two dirt shades).
- **The bot** cannot wall jump, ride platforms or take the one-way platforms; it proves the ground route, and the chimney has its own controller test.
- **Windows and macOS** are not run; Linux was (X11 with Vulkan; the Wayland driver aborts in GLib's settings schema on this machine, as it does for the UI playground, so `SDL_VIDEODRIVER` falls back to X11). The new code has no OS-specific parts. Hosted CI has not seen these commits.
- The work is uncommitted.
